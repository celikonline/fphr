# TK-032 — Harcama kalemi ReceiptFileId sunucu tarafı doğrulaması

**Durum:** inceleme — İNSAN ONAYI gerekli (bordro/ödeme alanı) (2026-09-27)

## Sorun
`POST/PUT api/v1/expense/claims/{id}/items` `ReceiptFileId`'yi serbest metin kabul ediyordu (yalnız kırpma).
Bordro, `ReceiptFileId` dolu onaylı kalemi `IApprovedExpensePayoutReader.ApprovedExpenseTotal` içinde vergisiz geri
ödeme olarak NET'e ekliyor; fişsiz kalem `UndocumentedExpenseTotal`'a düşüyor. API'yi doğrudan çağıran çalışan,
herhangi bir metin göndererek fişsiz kalemi fişli gösterebiliyordu. Web ve mobil bugün hep `null` gönderiyor.

## Yapılan
- `ExpenseClaimCommands.cs` — `ReceiptDocuments.ResolveAsync`: boş/null → `null` (sorgu yok). Doluysa GUID olmalı,
  `IDocumentAttachmentLookup.GetActiveAsync(tenant, [id])` ile aynı kiracıda Active belge bulunmalı ve talep sahibine
  ait olmalı: `EmployeeId == talep.EmployeeId` **ya da** (`EmployeeId == null` **ve** `UploadedBy == çağıran kullanıcı`,
  yani self-servis yükleme). Aksi her durumda `expense.item.receipt_not_found` (Validation); kalem eklenmez/değişmez.
  Geçerli kimlik kanonik GUID biçiminde saklanır. `AddExpenseItemHandler` ve `UpdateExpenseItemHandler` kullanır.
- Leave'in `LeaveRequestAttachmentLinker` kuralından **bilinçli fark**: Leave `UploadedBy == çağıran` ise belge başka
  çalışana bağlı olsa da kabul ediyor. Burada başka çalışana dosyalanmış belge (ör. İK kullanıcısının yüklediği
  başka çalışanın belgesi) kendi fişi sayılmıyor — bordro etkisi olduğu için sıkı kural.
- `Sense.Modules.Expense.Application.csproj` → `Documents.Contracts` referansı (Leave ile aynı; mimari testi yalnız
  Contracts'a izin veriyor). `IDocumentAttachmentLookup` hem Api hem Worker'da `AddDocumentsCoreServices` ile kayıtlı.
- `SharedResource{,.en}.resx` — `expense.item.receipt_not_found`.
- Testler: `ExpenseReceiptValidationTests.cs` (GUID olmayan / yol benzeri / var olmayan / başka çalışanın /
  çağıranın başka çalışan için yüklediği → hata; self-servis yükleme ve çalışana dosyalanmış belge → ok; null ve boşluk →
  ok, sorgu yok; güncellemede yabancı/var olmayan → hata ve kalem değişmez, kendi → ok, temizleme → ok).
  `ExpenseInputLimitsTests.cs` yeni kurucu imzasına uyarlandı.

## Veri
Demo DB (`expense.expense_items`): 2 kalem, `receipt_file_id` dolu 0 → veri göçü/temizlik gerekmez.
Diğer ortamlarda birleştirmeden önce aynı sorgu çalıştırılmalı:
`select count(*) from expense.expense_items where receipt_file_id is not null;` — dolu satır varsa bunlar
doğrulanmamış değerlerdir, bordroya girmeden önce insan kararı gerekir.

## Kapsam dışı / açık noktalar (insan kararı)
1. **Aynı fişin tekrar kullanımı:** aynı belge kimliği birden çok kaleme/talebe bağlanabiliyor (çift ödeme riski).
   Engellemek istenirse ayrı iş (benzersizlik kontrolü).
2. **Belge içeriği:** çalışan herhangi bir dosyayı yükleyip fiş diye bağlayabilir; bu doğrulama yalnız sahipliği
   garanti eder, içerik kontrolü onaycının işi.
3. **Gönderim sonrası belge silme:** doğrulama ekleme/güncelleme anında; kalem gönderildikten sonra belge silinirse
   bordro yine vergisiz sayar. Bordro okuyucusu (`ApprovedExpensePayoutReader`) değiştirilmedi.
4. Web/mobil fiş yükleme akışı henüz yok; eklendiğinde self-servis yüklemenin döndürdüğü belge kimliği
   `receiptFileId` olarak gönderilmeli.
