# B15 — Onboarding zenginleştirme (E5 backend)

Dal: takim/B15. Kapsam: yalnız Onboarding modülü + resx (tr/en, sona ekleme) + Onboarding testleri.

## Eklenenler
- Domain: `OnboardingCategory`, `OnboardingTemplateSet` (aşamaya bağlı, `uuid[]` şablon listesi), `OnboardingImportance` (Normal/High/Critical).
- `OnboardingTaskTemplate`: `CategoryId?`, `Importance`, `RequiresEDocument` (Create/Update'te sona opsiyonel parametre; eski çağrılar geçerli).
- `EmployeeOnboardingTask`: şablondan anlık kopya `CategoryId/Importance/RequiresEDocument` + `TemplateSetId?`.
- Application: `CategoryFeatures` (liste/oluştur/güncelle + `OnboardingCategoryProgress.Compute`: done/total, muaf hariç), `TemplateSetFeatures`, `StartProcessCommand` (set başına çalışan için tek kez -> `onboarding_template_set.already_started`, 409).
- Materializer: `MaterializeFromAsync` (set için); eski `MaterializeAsync` davranışı aynı, kategorisiz şablonlar çalışır.
- API (`/api/v1/onboarding`): `GET/POST categories`, `PUT categories/{id}`, `GET/POST template-sets`, `PUT template-sets/{id}`, `POST employees/{id}/start-process {templateSetId, referenceDate}`, `GET employees/{id}/category-progress`. Şablon isteği/DTO'larına `categoryId, importance, requiresEDocument`; checklist DTO'larına aynı alanlar (+ task DTO `templateSetId`).
- İzinler: yeni izin yok; kategori/set yönetimi `onboarding.templates.manage`, liste/ilerleme `onboarding.tasks.view`, başlatma `onboarding.tasks.manage`.
- Migration: `OnboardingCategoriesAndTemplateSets` (dotnet-ef ile üretildi). Mevcut satırlar için `importance` varsayılanı "Normal".
- resx: 10 yeni hata anahtarı (tr+en) — `SharedResource*.resx` sonuna eklendi.

## Notlar / endişeler
- Şablon oluşturma/güncellemede `CategoryId`'nin varlığı doğrulanmıyor (FK yok, modül içi tutarlılık web seçicisine bırakıldı).
- Şablon seti güncellenince mevcut çalışanlara başlamış görevler etkilenmez (anlık kopya).
- Pasif şablon set başlatılırken atlanır; set pasifse 409.
- Riskli alan: migration (`Onboarding/.../Migrations/**`) — insan onayı gerekir.

## Düzeltme turu 1/5 — referans bütünlüğü
- **İNSAN AKSİYONU: migration onayı** (`OnboardingCategoriesAndTemplateSets` yeniden üretildi; artık FK içerir; henüz birleşmedi).
- Şablon oluşturma/güncellemede `CategoryId` doluysa kategori aynı tenant'ta var ve aktif olmalı (güncellemede şablonun mevcut, değişmeyen kategorisi pasif olsa da kabul); yoksa `onboarding.category_not_found` (422 doğrulama; tr/en resx). Tenant filtresi repository sorgusundan gelir.
- Şema: `task_templates.category_id -> categories.id` FK, `ON DELETE RESTRICT`.
- Yeni `DELETE /onboarding/categories/{id}`: kategori bir şablonda kullanılıyorsa 409 `onboarding.category_in_use` (resx tr/en); kullanılmıyorsa silinir. Silme yoksa şablon `CategoryId` hiç sıfırlanmaz (kullanımdayken silme engelli). Görev satırlarındaki `CategoryId` anlık kopyadır (FK yok); silinmiş kategori ilerlemede "kategorisiz" sayılır.
- Set: mevcut doğrulama (aynı tenant + aynı aşama şablonu) yok/başka-tenant kimliği için testle kilitlendi.
- Testler (`OnboardingReferenceIntegrityTests`): unknown/other-tenant/inactive category, update, delete in use, set unknown template, set sırası korunur, model FK Restrict, migration importance varsayılanı "Normal". Test projesine Infrastructure proje referansı eklendi.
- Not: "kırmızıyı gör" — testler uygulamadan sonra yazıldı (derleme kırmızısı hariç); kırmızı aşaması ayrıca gösterilmedi.
