## Kabul maddeleri (plan Task B12)
1. `Acknowledge_sets_timestamp_and_ip_once` → `Payslip.Acknowledge` (sunucu zamanı + IP + User-Agent, bir kez).
2. `Acknowledge_before_publish_fails` → yayınlanmamış / dönemi Paid-Locked olmayan bordroda `payroll.errors.payslip_not_published` (422).
3. `Object_starts_PayslipObjection_workflow` → `IWorkflowService.StartAsync("PayslipObjection", payslipId, employeeId, …)`.
4. `Objection_accepted_marks_status_and_notifies_payroll_role` → `ApprovalCompleted` → `ObjectionStatus=Accepted` + `PayslipObjectionAccepted` (NotifyRoleCode `PayrollSpecialist`) outbox'a.
5. `Reminder_targets_only_unacknowledged_published` → yayınlanmış, onaylanmamış, itirazı bekleyen/kabul edilmemiş, dönemi Paid/Locked bordrolar.
6. `Employee_cannot_read_others_payslip` → başkasının bordrosu liste/PDF/onay/itirazda 404 (`payroll.payslip.not_found`).

## Davranış
- Dönem `mark-paid` → dönemin tüm bordroları `PublishedAt` alır (idempotent). Yeniden açılan (Open) dönemin bordroları gizlenir, onay/itiraz reddedilir.
- `Payslip.Recalculate` → önce mevcut onay / karara bağlanmış itiraz `AcknowledgementHistory`'ye (jsonb, salt-ekleme) arşivlenir, sonra `PublishedAt`/onay alanları sıfırlanır (yeni versiyon yeniden yayın + onay ister); bekleyen itiraz canlı kalır, Workflow'da sürer.
- Uçlar: `GET v1/payroll/me/payslips`, `GET …/{id}/document`, `POST …/{id}/acknowledge`, `POST …/{id}/object` (`{ reason }` → güncel satır, tur 2), hepsi `payroll.my.payslip`.
  Elle hatırlatma: `POST v1/payroll/periods/{id}/payslip-reminders` (`payroll.period.approve`, sayı döner).
- Günlük iş: `JobType.PayslipAcknowledgementReminder` (`PayslipAcknowledgementReminderJobHandler`, PayrollModule'de kayıtlı), seed 10:00.
- Workflow gelen kutusu özeti: `PayslipObjectionApprovalSummaryProvider` (dönem etiketi + gerekçe, tutar yok).

## Düzeltme turu 2 (bağımsız inceleme: 2 Important + Minor)

### 1) İyimser eşzamanlılık (xmin)
- Projede xmin/RowVersion kalıbı yoktu; `GlobalExceptionHandler` zaten `DbUpdateConcurrencyException` → 409 `general.concurrency_conflict` eşliyor.
- `Payslip`'e gölge concurrency token: `b.Property<uint>("RowVersion").HasColumnName("xmin").HasColumnType("xid").IsRowVersion()` (`PayrollDbContext.cs`).
- Yeni port `IPayslipChangeSaver` (Application) / `PayslipChangeSaver` (Infrastructure): değişikliği komut transaction'ı içinde hemen yazar,
  `DbUpdateConcurrencyException` → `Error.Conflict("payroll.errors.payslip_concurrent_update")` (409; resx tr/en sona eklendi).
  - `/acknowledge`: onay → hemen kaydet → kaybeden 409, kanıt ilk kazananın kalır.
  - `/object`: itiraz Pending olarak **Workflow çağrılmadan önce** kaydedilir; yarışı kaybeden 409 alır ve onay isteği hiç açılmaz.
    Workflow başarısız olursa itiraz geri alınıp yeniden kaydedilir (komut transaction'ı başarısız sonuçta da commit eder).
  - `Recalculate` (dönem hesap komutları) ve Worker'daki itiraz karar işleyicileri: xmin artık onları da korur; çakışma pipeline'da
    `DbUpdateConcurrencyException` olarak yükselir → API'de global 409 `general.concurrency_conflict` (yerelleştirilmiş), Worker'da outbox yeniden dener.
    Hesaplama servisine (para kodu) dokunulmadı.
- Migration: aynı ad, yeniden üretildi. C# dosyasında `AddColumn<uint>("xmin", rowVersion: true)` görünür ama Npgsql SQL üreticisi
  sistem kolonunu atlar — `dotnet ef migrations script AddPayslipPaymentConfirmedAt AddPayslipAcknowledgementAndObjection` çıktısı
  yalnız 10 `ALTER TABLE … ADD` içeriyor, xmin DDL'i yok (doğrulandı). Snapshot farkı yalnız `RowVersion` (xmin) özelliği.
