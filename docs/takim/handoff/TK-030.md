## Planlama bulguları

Sınıflandırıcı engeli kalksa bile kart bugünkü backend'le yapılamaz:
- Çalışanın kendi pusulalarını listeleyen uç YOK. Mevcut `GET api/v1/payroll/employees/{employeeId}/payslips`
  (`PayslipsController.cs:26`) ve PDF ucu (`:18`) `payroll.trace.view` ister; çalışan rolünde bu izin yok
  (`SystemRoleDefinitions.cs:70`, yalnız `*.self.*`/`*.my.*`/`me.*`), mobil 403 alır.
- "Okudum/onaylıyorum" uç ve alanı YOK. `Payslip`'te görüntüleme/onay alanı yok; `payroll.payslip.acknowledge`
  yalnız ileride diye not düşülmüş (`PayrollPermissions.cs:9`). Tasarım yalnız dokümanda
  (`docs/analysis/kolayik-video/11.3.07-bordro.md`, `PayslipDelivery{ViewedAt, AcknowledgedAt}`).
- Kısa yol YASAK: çalışan rolüne `payroll.trace.view` vermek, handler'lar veri kapsamı kontrol etmediği için
  kiracının tüm bordrolarını açar. Bu kapsam açığı ayrı iş olarak işaretlendi.

Önerilen sözleşme (insan onayı olmadan uygulanmaz): `GET payroll/payslips/my`,
`GET payroll/payslips/my/{id}/document` (başkasınınsa 404), `POST payroll/payslips/my/{id}/acknowledge`
(idempotent), yeni izin `payroll.my.payslips`. Parçalar: (1) dotnet — sorgu/PDF/onay + migration (riskli),
(2) node — mobil `PayrollService.ts` + test, (3) node — `PayrollScreen.tsx` (riskli listede).
