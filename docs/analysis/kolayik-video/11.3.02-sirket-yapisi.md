# 11.3.2 Şirket Yapısı

## Plan Kararları

**[Video] Ek bulgular** (ayrıntı Bölüm 11.3.2):
- **FARKLI — Seviyeler sıralı ve kiracı tarafından düzenlenir** [Ekranda]: hazır zincir **Şirket > Şube > Departman > Ünvan**; iki seviye arasındaki **"+"** ile araya yeni seviye (**Proje**; en alta **Onay süreci birimi**), seviye yanındaki **üç nokta → Sil** ile seviye kaldırma (örn. Şube). `OrgUnitType.Level` → `SortOrder` (kiracı düzenler, aralıksız 1..n), `IsActive`; `Company` türü `IsSystem` (silinemez, en az bir aktif seviye).
- **FARKLI — Ünvan bir seviyedir** [Ekranda]: `JobTitle` ayrı entity olmaktan çıkar → seed `OrgUnitType{Code=Title}`. Varsayılan aktif seed: Company, Branch, Department, Title; pasif seed (kiracı "+" ile açar): Team, Project, ApprovalUnit; adlar kaynak anahtarlı (`unit_types.{code}.name`, tr/en), kiracının eklediği tür `CustomName` taşır. Plan `Position` (kadro/headcount) opsiyonel kalır ve `OrgUnit(Title)`'a referans verir.
- **DETAY — Birimler seviye içinde düz liste** [Ekranda]: sağ panelde her seviye ayrı liste (**Yeni ekle**), üst birim seçimi gösterilmedi → `OrgUnit.ParentId` opsiyonel (`TenantSettings.Organization.RequireParentLink=false`); çalışanın konumu seviye başına bir birimden oluşan demet (`EmployeeOrgAssignment`), devralma/kapsam çözümü ParentId ağacından değil bu demetin `SortOrder` sırasından yapılır. Kolay İK "Pozisyon" = birim demeti + yönetici + pozisyon başlama tarihi (kariyer kaydı), kadro değil.
- **YENİ — Seviye silme kuralı**: seviyedeki bir birimde aktif çalışan ataması varsa 409 `organization.unit_type.in_use`; `organization.structure.manage` + onay diyaloğuyla "atamaları kapat ve sil" (`EmployeeOrgAssignment.ValidTo=bugün`, kariyer geçmişi korunur); atamasız seviye pasifleşir (birimleri ile birlikte, geçmiş kayıtlar kalır); seviyeye bağlı onay süreci atamaları ve birim yetkilendirmeleri `OrgUnitTypeRemoved` event'i ile temizlenir.
- **YENİ — Şirket biriminde Tatil takvimi** [Ekranda]: Şirket **Yeni ekle** = **Ad** + **Tatil takvimi** (**"Türk resmi tatil takvimi"**); "en alt yapıya kadar bütün yapılara" uygulanır, resmi tatiller otomatik gelir ve ana sayfada listelenir. `PublicHoliday` → `HolidayCalendar{Code, NameKey?, CustomName?, CountryCode, IsSystem, IsActive}` + `HolidayCalendarEntry{Date, NameKey?/Name, IsHalfDay, Kind}`; `Company.HolidayCalendarId`; çözümleme: çalışanın Company ataması → `Company.HolidayCalendarId` → `TenantSettings.Organization.DefaultHolidayCalendarCode`("TR"); `IHolidayCalendarLookup` kontratı (Leave gün sayımı, Attendance puantaj, ana sayfa). TR seed girişleri yıl bazlı veri dosyasından (kodda tarih sabiti yok).
- **YENİ — Birime onay süreci ataması** [Ekranda]: birim **üç nokta → Düzenle → Opsiyonel alanlar** (**İzin / Avans / Harcama / Fazla mesai onay süreci**) → `OrgUnit.ApprovalPolicyAssignments[]{RequestType, ApprovalPolicyId}` (Workflow'a yalnız Id referansı, Contracts üzerinden); `IOrgApprovalPolicyResolver`: çalışanın demetinde en alt seviyeden yukarı ilk atama, yoksa Workflow varsayılanı (ilk yönetici) → bkz. 3.4 / 11.3.4.
- **YENİ — Birim yetkilendirme** [Ekranda]: birim **üç nokta → Birim yetkilendirme** → kişi + **"Çalışanların ödeme ve maaş bilgilerine erişebilsin"** / **"Kendi biriminin raporlarına erişebilsin"** → `OrgUnitAuthorization{OrgUnitId, EmployeeId, CanViewSalary, CanViewUnitReports}`; aynı kişi birden çok birime; `OrgUnitAuthorizationChanged` → Identity Department/Custom kapsam çözümü + `pv` invalidation → bkz. 11.3.1.
- **DETAY — "Onay süreci birimi" pratiği** [Ekranda]: yalnız onay yönlendirme için en alta eklenen seviye ("Bilgi İşlem 1/2", "Müşteri İlişkileri 1…4"); seed pasif `ApprovalUnit` türü; toplu atama özlük aktarımı **Sadece güncelleme modu** ile → bkz. 11.3.15.
- **DETAY — Şube ↔ Lokasyon** [Ekranda]: Kolay İK'da Şube yalnız ad; SenseİK `OrgUnit(Branch).LocationId?` opsiyonel bağ (adres/geofence `Location`'da kalır, Location Branch'siz de olabilir — PDKS noktası).
- **DETAY — Yönetici ataması** [Ekranda]: **Çalışanlar → Organizasyon şeması** → kişi → **Düzenle**; toplu **İşlem tipi seç → Yönetici ata**; tekil **Kariyer → Pozisyon → Düzenle** → `Employee.DirectManagerId` (→ 11.3.3). Organization yalnız `GET /organization/org-chart` (Employee hiyerarşi kontratından) + yetkiliye düzenleme kısayolu; çalışana görünürlük erişim anahtarı `Access.OrgChartVisibleToEmployees` (→ 11.3.1).
- **DETAY — Çalışma tipleri kiracı listesi** [Ekranda, ATS]: ATS **Ayarlar → Şirket → Çalışma tipleri** (Tam zamanlı, Yarı zamanlı, Staj) + özlük şablonu "Çalışma şekli" listesi → `Employee.EmploymentType` enum yerine Organization'da kiracı düzenlenebilir `EmploymentType{Code, NameKey?, CustomName?, IsSystem, IsActive}` (seed FullTime, PartTime, Temporary, Contract, Freelance, Intern, Mobile); Employee ve Recruitment `IEmploymentTypeLookup` ile kullanır (→ 11.3.11).
- **DETAY — Birlikte istihdam bayrağı** [Mevzuat]: `Company.JointEmploymentGroupCode?` — aynı koddaki şirketlerde geçen süreler kıdem/izin kıdeminde toplanır, iş güvencesi 30-çalışan sayımı birleşik yapılır; fasılalı çalışma dönemleri birleşir (→ 11.3.3, 11.3.5, 11.3.7).
- **YENİ — Permission anahtarları** (`OrganizationPermissions.Module="organization"`; DB şeması `org` değişmez): `organization.structure.view`, `organization.structure.manage`, `organization.unit.authorize`, `organization.company.view`, `organization.company.manage`, `organization.location.manage`, `organization.calendar.manage`, `organization.orgchart.view`. Owner/Admin/HR tümü; HRSpecialist view + orgchart; Auditor tüm view; Employee/Manager yalnız `orgchart.view`.
- **YENİ — Event'ler**: `OrgUnitTypeAdded/Removed/Reordered`, `OrgUnitCreated/Renamed/Deactivated`, `OrgUnitApprovalPolicyAssigned`, `OrgUnitAuthorizationChanged`, `CompanyHolidayCalendarChanged`, `HolidayCalendarEntriesChanged` (Leave bekleyen taleplerde gün sayısı, Attendance açık dönemler yeniden değerlendirilir; kilitli dönem değişmez).
- **DETAY — Ekran**: AD "Birim ağacı (sürükle-bırak)" yerine **iki panelli Şirket yapısı** (`/admin/organization/structure`: sol seviyeler + "+" + satır menüsü, sağ seçili seviyenin birim gridi + **Yeni ekle**; satır: Düzenle / Onay süreçleri / Birim yetkilendirme / Pasifleştir); `/admin/organization/holiday-calendars`; "Pozisyonlar/Unvanlar" ekranı Ünvan seviyesine katlanır; Kariyer → Pozisyon formu ve import şablonu kolonları `GET /organization/unit-types` listesinden dinamik. Faz 0 madde 12 ve 20 buna göre güncellenir.
- **DETAY — Öneriler** [Aday]: `OrgUnitType.AllowsMultipleAssignment` (Proje türünde çoklu atama; birlikte istihdamda çoklu şirket hizmeti), `Location.HolidayCalendarId?` lokasyon bazlı takvim override (ülke farkı), kiracı aktivasyon kontrol listesinde adım 1 "Şirket yapısı" (→ 11.3.13).

## Ayrıntılı Bulgular

#### 11.3.2 Şirket yapısı
**Kaynak videolar**: part8 #21 (şirket yapısı ve faydaları), #26 (aktivasyon adımı 1: seviyeler, tatil takvimi), #33 (onay süreçleri: org şeması, opsiyonel alanlar, onay süreci birimi), #24 (yönetici atama), #32 (birim yöneticisi), #18/#25 (Kariyer → Pozisyon ekle), #10 (erişim ayarı: organizasyon şeması); part2 #1 (ATS Ayarlar → Şirket); part1-condensed (esnek birim türleri, özlük şablonu birim/çalışma şekli kolonları); part3 #2 ve part5 #3 (birlikte istihdam, mevzuat).

**Ekranlar ve menüler**
- **Ayarlar → Şirket bilgileri** [Ekranda, part8 #26]: sol panel hiyerarşi seviyeleri yukarıdan aşağı **Şirket**, **Şube**, **Departman**, **Ünvan**; iki seviye arasındaki **"+"** → seviye adı (örn. **Proje**) → **Kaydet**; seviye yanında **üç nokta → Sil** (örn. Şube). Sağ panel: her seviye için birim listesi/sütunu ve **Yeni ekle** butonu. SenseİK: `/admin/organization/structure` (iki panel), `OrgUnitType` + `OrgUnit`.
- Şirket seviyesinde **Yeni ekle** [Ekranda, part8 #26]: **Ad** (örn. "Kolay İK") + **Tatil takvimi** (**"Türk resmi tatil takvimi"**) → **Kaydet**. Diğer seviyelerde yalnız **Ad** (Şube; Departman: Finans, İnsan Kaynakları, Yazılım; Proje: A Projesi, B Projesi; Ünvan: İK Uzmanı). SenseİK: `OrgUnit(Company)` + `Company{HolidayCalendarId}` atomik oluşur; tüzel kişilik alanları `/admin/organization/companies/:id` (Şirket profili) ekranında sonradan.
- Birim satırı **üç nokta → Düzenle** → **Opsiyonel alanlar**: **İzin onay süreci**, **Avans onay süreci**, **Harcama onay süreci**, **Fazla mesai onay süreci** [Ekranda, part8 #33]; Departman, Ünvan ve "Onay süreci birimi" seviyelerinde aynı. SenseİK: `OrgUnit.ApprovalPolicyAssignments` → bkz. 11.3.4.
- Birim satırı **üç nokta → Birim yetkilendirme** → yetkili adı + anahtarlar **"Çalışanların ödeme ve maaş bilgilerine erişebilsin"**, **"Kendi biriminin raporlarına erişebilsin"** → **Kaydet** [Ekranda, part8 #21, #32]. SenseİK: `OrgUnitAuthorization` → bkz. 11.3.1.
- **Ayarlar → Şirket bilgileri → Onay süreçleri** [Ekranda, part8 #33] → bkz. 11.3.4.
- **Çalışanlar → Organizasyon şeması** [Ekranda, part8 #33]: yönetici–ast ağacı; kişi seçilip **Düzenle** ile yöneticisi atanır. Çalışanlara görünürlük **Erişim ayarları → Organizasyon şeması** anahtarı [Ekranda, part8 #10]. SenseİK: `/app/directory/org-chart`, `organization.orgchart.view`, `Access.OrgChartVisibleToEmployees` → bkz. 11.3.1.
- Çalışan kartı **Kariyer → Pozisyon ekle** [Ekranda, part8 #21, #33]: seviyeler sırayla seçilir (**Şirket, Şube, Departman, Proje, Ünvan, Onay süreci birimi**) + **Yönetici**; **Pozisyon → Düzenle** ile değiştirilir [part8 #24]. SenseİK: form alanları `GET /organization/unit-types` (aktif, SortOrder) listesinden dinamik → bkz. 11.3.3.
- **Toplu işlemler → İşlem tipi seç → Yönetici ata** → yönetici adı → Devam [Ekranda, part8 #24] → bkz. 11.3.3.
- **Ana sayfa → Resmi tatiller** (şirketin tatil takvimine göre) [Ekranda, part8 #21] → bkz. 11.3.13.
- ATS **Ayarlar → Şirket** [Ekranda, part2 #1]: **Organizasyon ekle** (şirket adı) → **Departman ekle** (Muhasebe, İnsan Kaynakları, Teknoloji) → **Takım ekle** (Ön muhasebe, Backend, Frontend); **Konumlar** (Kadıköy şubesi, Ankara şubesi, **Uzaktan**); **Çalışma tipleri** (Tam zamanlı, Yarı zamanlı, Staj). SenseİK: tek yapı; Takım = `OrgUnitType Team`, Konum = `Location` (tür Uzaktan), Çalışma tipi = `EmploymentType` lookup → bkz. 11.3.11.

**Alanlar**
- Seviye (birim türü): **Ad**; eklendiği konum (hangi iki seviyenin arası) → `OrgUnitType{Code, NameKey?, CustomName?, SortOrder, IsActive, IsSystem, AllowsNesting}`. Seed türler `NameKey` (`unit_types.{code}.name`), kiracı türleri `CustomName`.
- Birim: **Ad**; Şirket seviyesinde ek **Tatil takvimi**; tüm seviyelerde **Opsiyonel alanlar** (4 onay süreci) → `OrgUnit{TypeId, ParentId?, Code?, Name, ManagerEmployeeId?, CostCenterId?, LocationId?, IsActive}`, `OrgUnitApprovalPolicyAssignment{OrgUnitId, RequestType, ApprovalPolicyId}`.
- Şirket (SenseİK eki; videoda yalnız Ad + Tatil takvimi görüldü): `Company{OrgUnitId, LegalName, TaxOffice, TaxNo, MersisNo, SgkRegistrationNo, NaceCode, Address, IsDefault, HolidayCalendarId, JointEmploymentGroupCode?}`.
- Birim yetkilendirme: **kişi** + 2 anahtar → `OrgUnitAuthorization{OrgUnitId, EmployeeId, CanViewSalary, CanViewUnitReports}`.
- Çalışan pozisyonu (kariyer kaydı): seviye başına bir birim + **Yönetici** + **Pozisyon başlama tarihi** (işe başlamadan farklı olabilir [part1]) → `EmployeeOrgAssignment{EmployeeId, OrgUnitTypeId, OrgUnitId, ValidFrom, ValidTo}` → bkz. 11.3.3.
- Özlük aktarım şablonu birim kolonları: **şirket, şube, departman, ünvan, onay süreci birimi** (özel seviyeler dahil), **ilk yönetici**; yönetici/birim önceden tanımlı olmalı [Ekranda, part1, part8 #33] → bkz. 11.3.15.
- Tatil takvimi: `HolidayCalendar{Code, NameKey?, CustomName?, CountryCode, IsSystem, IsActive}`, `HolidayCalendarEntry{CalendarId, Date, NameKey?, Name?, IsHalfDay, Kind(Official/Religious/Company)}`.
- Çalışma tipi: `EmploymentType{Code, NameKey?, CustomName?, IsSystem, IsActive}` (seed: FullTime, PartTime, Temporary, Contract, Freelance, Intern, Mobile — part1 "Çalışma şekli" listesi; ATS: Tam zamanlı, Yarı zamanlı, Staj).

**İş kuralları ve hesaplama**
- Hazır hiyerarşi hesap açılışında gelir; seviyeler eklenip çıkarılabilir; örnek sonuçlar **Şirket > Departman > Proje > Ünvan** [part8 #21] ve **Şirket > Şube > Proje > Departman** [part8 #26] [Ekranda].
- Şirket tatil takvimi "en alt yapıya kadar bütün yapılara etki eder"; resmi tatiller otomatik gelir; ana sayfada listelenir [Ekranda, part8 #21, #26].
- Yapının faydası çalışan atamasıyla başlar: raporlarda birim filtresi, onay süreçlerinin departman bazlı atanması, birim yetkilendirme [Ekranda, part8 #21].
- Onay süreci devralma: alt kırılımda süreç tanımlı değilse üst kırılımdaki süreç varsayılan alınır; hiçbiri yoksa **ilk yönetici** [Ekranda, part8 #33] → bkz. 11.3.4.
- Birim yetkilendirme: yalnız kendi birimindeki çalışan kartları; aynı kişi birden çok birime yetkilendirilebilir; maaş görünürlüğü anahtara bağlı [Ekranda, part8 #32] → bkz. 11.3.1.
- "Onay süreci birimi" pratiği: aynı departmanda farklı süreçler gerekiyorsa en alta seviye ekle → birimleri oluştur (Bilgi İşlem 1/2, Müşteri İlişkileri 1…4) → çalışanların kariyerine yaz → sürece ata; çok kişide Excel + **Sadece güncelleme modu** [Ekranda, part8 #33].
- ATS: Organizasyon/Departman/Takım + Konum + Çalışma tipi seçilmeden ilan açılamaz [Ekranda, part2 #1] → bkz. 11.3.11.
- Birlikte istihdam [Mevzuat, part3 #2, part5 #3]: aynı grup/holding şirketlerinde geçen süreler kıdem tazminatı ve izin kıdeminde toplanır; iş güvencesi 30-çalışan eşiğinde birlikte istihdam varsa toplam sayı; fasılalı çalışma dönemleri birleştirilir → bkz. 11.3.3, 11.3.5, 11.3.7.
- SenseİK seviye kuralları: `SortOrder` aralıksız, "+" araya ekleme yeniden numaralar; `Company` `IsSystem` ve silinemez; en az bir aktif seviye; yeniden adlandırma serbest (`CustomName` `NameKey`'i geçersiz kılar); `IOptions<OrganizationOptions>.MaxUnitTypes` (varsayılan 10).
- SenseİK seviye silme: birimlerde aktif `EmployeeOrgAssignment` varsa 409 `organization.unit_type.in_use`; onay diyaloğu + `organization.structure.manage` ile "atamaları kapat ve sil" (`ValidTo=bugün`, geçmiş korunur); atamasız seviye ve birimleri pasifleşir (soft delete); bağlı onay süreci atamaları/yetkilendirmeler `OrgUnitTypeRemoved` ile temizlenir.
- SenseİK birim kuralları: ad tür (+ParentId) içinde unique; `Code` opsiyonel unique; aktif atamalı birim silinemez → pasifleştirme; pasif birime yeni atama yapılamaz; `ParentId` verilirse üst birimin türü daha küçük `SortOrder`'da olmalı; `TenantSettings.Organization.RequireParentLink=false`.
- SenseİK tatil çözümleme: çalışan → Company ataması → `Company.HolidayCalendarId` → `TenantSettings.Organization.DefaultHolidayCalendarCode`("TR"); takvim değişince `CompanyHolidayCalendarChanged` → Leave bekleyen taleplerin gün sayısı, Attendance açık dönemler yeniden değerlendirilir (kilitli dönem değişmez) → bkz. 11.3.5, 11.3.6.
- SenseİK onay atama çözümleme: `IOrgApprovalPolicyResolver.ResolveAsync(employeeId, requestType)` → aktif atama demeti `SortOrder` azalan (en alt seviye önce: ApprovalUnit > Title > Department > Branch > Company) → ilk `ApprovalPolicyAssignment`; sonuç yalnız `ApprovalPolicyId` (Organization Workflow'u referans etmez) → bkz. 11.3.4.
- SenseİK yetkilendirme çözümleme: Identity `IDataScopeService` Department/Custom kapsamını `IOrgUnitAuthorizationLookup` + atama demeti ile çözer; `CanViewSalary` → `employee.salary.view@Custom(unitIds)`, `CanViewUnitReports` → `reporting.reports.view@Custom(unitIds)` → bkz. 11.3.1, 11.3.12.

**Akışlar**
1. Aktivasyon adımı 1 [part8 #26]: **Ayarlar → Şirket bilgileri** → seviyeleri düzenle ("+" / üç nokta → Sil) → Şirket **Yeni ekle** (Ad + Tatil takvimi) → Şube / Proje / Departman / Ünvan birimlerini **Yeni ekle** ile gir.
2. Çalışana atama [part8 #21]: **Çalışanlar** → kart → **Kariyer → Pozisyon ekle** → seviye seçimleri (Şirket, Departman, Proje, Ünvan) → **Kaydet** → çalışan "İK departmanında, A Projesinde, İK Uzmanı".
3. Yönetici atama [part8 #24, #33]: toplu (**Toplu işlemler → İşlem tipi seç → Yönetici ata**) / tekil (**Kariyer → Pozisyon → Düzenle**) / org şemasından (**Düzenle**) → bkz. 11.3.3.
4. Birim yetkilendirme [part8 #21, #32]: birim **üç nokta → Birim yetkilendirme** → kişi → anahtarlar → **Kaydet** → kişi o birimin kartlarını görür/düzenler, birimine çalışan ekler.
5. Onay süreci atama [part8 #33]: **Onay süreçleri → Yeni süreç ekle** → birim **üç nokta → Düzenle → Opsiyonel alanlar** → süreç seç → **Kaydet**; gerekiyorsa en alta "Onay süreci birimi" seviyesi + toplu güncelleme → bkz. 11.3.4, 11.3.15.
6. Seviye kaldırma [part8 #26]: seviye **üç nokta → Sil** (SenseİK: dolu seviyede uyarı/engel, yukarıdaki kural).
7. Tatil takvimi bakımı (SenseİK): `/admin/organization/holiday-calendars` → TR sistem takvimini kopyala → şirket günü ekle (Kind=Company) → şirkete ata → `CompanyHolidayCalendarChanged`.
