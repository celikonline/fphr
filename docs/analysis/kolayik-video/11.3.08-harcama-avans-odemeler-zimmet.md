#### 11.3.8 Harcama, avans, ödemeler ve zimmet
**Kaynak videolar**: part8 #1 (harcama talebi), #13 (avans talebi), #8 (FM → ödeme), #18 ve #25 (çalışan kartı Ödemeler / Borç / Diğer), #10 (erişim ayarları: Dosyalar ve Zimmet), #29 (zimmet aktarım şablonu), #32 (birim yöneticisi ödeme/maaş anahtarı), #33 (talep türü başına onay süreci) + part8 "Veri aktarımı" ve "Bildirimler" bölümleri; part1 web ve mobil talep oluşturma videoları (mobil fiş OCR); part4 #3 (self-servis avans/harcama söylemi); part5 #7 (özlük dosyasında zimmet formu). part2/3/6'da bu kapsama ait ürün bulgusu yok.

**Ekranlar ve menüler**
- Sol menü **Talep** → **Harcama** / **Avans** (türler şirket politikasına göre listelenir; mobilde **"+"** hızlı talep butonu) [Ekranda, part1; part8 #1/#13].
- Harcama talebi ekranı: **Fiş ekle** butonu → fiş formu; fiş listesi + **toplam tutar**; **genel açıklama** alanı; **Gönder** → onay diyaloğu [Ekranda, part8 #1]. Mobilde **Harcamalar** girişi; **fiş görüntüsü kamerayla çekilir**, sistem tutar ve tarihi okuyup alanları doldurur [Ekranda, part1 mobil].
- Avans talebi formu → **Kaydet** [Ekranda, part8 #13]; web'de Avans → tutar → Kaydet, mobilde "+" → Avans → tutar → Devam → Gönder [Ekranda, part1].
- **Kendi hesabım → Ödemeler**: gönderilen harcama/avans taleplerinin detayı ve güncel durumu; ödemeye çevrilen FM'ler de burada [Ekranda, part8 #1/#13/#8].
- Çalışan kartı (İK/yönetici görünümü): **Ödemeler** sekmesi ("çalışana eklediğiniz bir ödeme olduğunda burada görürsünüz"), **Fazla mesailer**, **Borç(?)** barı ("çalışanın borcunu barda göreceksiniz"), **Diğer** → **Zimmetler / Eğitimler / Dosyalar** [Ekranda, part8 #18/#25].
- **Ayarlar → Erişim ayarları → Hesap** grubu: **Dosyalar** ve **Zimmet** anahtarları (açıksa çalışan kendi kartında kendi dosya/zimmetlerine erişir) [Ekranda, part8 #10] → sayfa tasarımı bkz. 11.3.1.
- **Ayarlar → Veri aktar → Zimmet**: Şablon indir → Dosya yükle → kolon eşleştirme → Sadece güncelleme modu → Kaydet ve devam et [Ekranda, part8 #29 + Veri aktarımı] → mekanik bkz. 11.3.15.
- Ayarlar → Şirket bilgileri → birim/unvan → üç nokta → Düzenle → **Opsiyonel alanlar** → **Avans onay süreci**, **Harcama onay süreci** [Ekranda, part8 #33] → bkz. 11.3.4.
- **Raporlar → Finans** kategorisi (maaş/ödeme içerir; Birim yöneticisinde anahtara bağlı) [Ekranda, part8] → bkz. 11.3.12.
- Ayarlar → **Ödeme bilgileri** = abonelik/faturalama bilgileri; erişim çelişkisi (hesap sahibi vs yönetici) bu kapsam dışı → bkz. 11.3.14.
- SenseİK eşlemesi: SS `/app/requests/new?type=expense|advance` (Talep menüsü tek giriş), `/app/payments` ("Ödemelerim"; sekmeler Tümü / Harcama / Avans / FM ödemeleri / Ek ödeme-kesinti), `/app/assets` ("Zimmetlerim"); AD `/admin/expenses/*` (Talepler, Avanslar, Kategoriler & limitler, Politikalar, Ek ödeme/kesinti, Banka ödeme listeleri), `/admin/employees/:id` sekmeleri **Ödemeler** ve **Diğer > Zimmetler**, `/admin/assets/*` (Envanter, Kategoriler, Zimmet ver/al, Aktarım), `/admin/settings/access` (Erişim ayarları), `/admin/settings/import` (→ 11.3.15).

**Alanlar**
- Fiş (`ExpenseItem`): **Kategori** (örn. "Yolculuk ve Ulaşım", "Yiyecek ve İçecek") → `CategoryId`; **Tutar** → `Amount`; **Fiş tarihi** → `ReceiptDate`; **Vergi oranı** → `TaxRate` (%, `TaxAmount` hesaplanır); **Para birimi** ("taraflara birini", doğrulanmalı) → `Currency`, `ExchangeRate`, `AmountInBaseCurrency`; **Dosya ekle** (fiş görseli; web'de dosya seç, mobilde kamera) → `ReceiptFileId` (`IFileStorage` anahtarı `{tenant}/expense/claim/{id}/{file}`); **Açıklama** (fiş bazlı, örn. "yemek harcaması") → `Description`; OCR: `OcrResult jsonb{Amount, Currency, Date, TaxRate, Vendor, Confidence}`, `OcrStatus`, `IsOcrPrefilled` [Ekranda, part8 #1; part1 web/mobil].
- Talep (`ExpenseClaim`): fiş listesi; **Toplam tutar** (otomatik) → `TotalAmount` (temel para birimi, hesaplanan); **Genel açıklama** (örn. "müşteri ziyareti") → `Description`; `Status(Draft→Submitted→Approved/Rejected/Returned→Paid)`, `ApprovalRequestId`, `SubmittedAt`, `PaymentMethod`, `PaidAt` [Ekranda].
- Avans (`AdvanceRequest`): **Tutar** → `Amount`; **Para birimi** (TL, Euro …) → `Currency`; **Tarih** (varsayılan bugün) → `RequestedDate`; **Taksit talebi** + **taksit sayısı** → `IsInstallmentRequested`, `InstallmentCount?` (1..`Expense.Advance.MaxInstallments`); **Açıklama** → `Description`; `Status`, `ApprovalRequestId`, `PaidAt`; `AdvanceInstallment{Sequence, PayrollPeriod, Amount, Status(Planned/Deducted/Cancelled)}` [Ekranda, part8 #13]. part1 web/mobil videosunda yalnız tutar giriliyor → tek zorunlu alan Tutar; kaynaklar çelişmiyor, doğrulanmalı.
- Ödemeler satırı (`PaymentOverviewRow`, projeksiyon): Tür (Harcama / Avans / FM ödemesi / Ek ödeme-kesinti), Tarih, Tutar + para birimi, Durum, Açıklama, detay bağlantısı; FM satırında çarpan ve net/brüt bilgisi (→ 11.3.5) [Ekranda, part8 #8/#13].
- Zimmet aktarım şablonu (`AssetImportRow`): **E-posta** (opsiyonel; doluysa aktarım sonrası bilgilendirme) → `Email?`; **Kimlik numarası** (sistemde kayıtlı TCKN; eşleştirme anahtarı, çalışan önceden kayıtlı olmalı) → `NationalId`; **Kategori** (telefon, tablet, bilgisayar, araba …; önceden tanımlı olması gerekmez) → `CategoryName`; **Seri numarası** (varsa; boş bırakılabilir) → `SerialNumber?`; **Zimmet veriliş tarihi** → `AssignedAt`; **İade tarihi** (varsa) → `ReturnedAt?`; **Açıklama** (zimmetin önemli detayları) → `Note?` [Ekranda, part8 #29].
- Zimmet (mevcut model üzerine eklenen/gevşetilen alanlar): `AssetCategory{Name, IsAutoCreated, CustomFieldSchema}`, `Asset{Code (otomatik), CategoryId, Name?, Brand?, Model?, SerialNumber?, Description, Status}`, `AssetAssignment{AssetId, EmployeeId, AssignedAt, ReturnedAt?, Note, Source(Manual/Import), NotifyEmployee, NotificationSentAt, Condition, ProtocolDocumentId, SignatureStatus}`.

**İş kuralları ve hesaplama**
- Harcama talebi ≥1 fiş içerir; fişler taslakta eklenir/çıkarılır; `TotalAmount = Σ AmountInBaseCurrency` sunucuda yeniden hesaplanır; `TaxAmount = Amount − Amount / (1 + TaxRate)` (tutar KDV dahil varsayımı; doğrulanmalı) [Ekranda + SenseİK kararı].
- Vergi oranı seçenekleri `LegislationParameter Vat.Rates` (tarih aralıklı; fiş tarihine göre geçerli liste); `ExpenseCategory.DefaultTaxRate` ön seçim; kodda sabit oran yok.
- Yabancı para fişte kur = fiş tarihindeki TCMB kuru (`IExchangeRateProvider`, Integrations.Contracts); kur bulunamazsa talep gönderilebilir, "kur bekliyor" uyarısı; bordro kalemi temel para biriminde [SenseİK kararı; Kolay İK davranışı belirsiz].
- OCR: `Expense.ReceiptOcr.Enabled` açıksa fiş görseli yüklenince `IReceiptOcr` çağrılır; `Confidence ≥ MinConfidence` olan alanlar ön doldurulur, kullanıcı düzenleyip kaydeder; sonuç `OcrResult`'ta saklanır, kullanıcı alanı değiştirirse `IsOcrPrefilled=false` (audit). Kolay İK yalnız mobilde gösterdi; SenseİK web'de de uygular [Aday, öneri]. Ai modülü kapalıysa/kota doluysa özellik gizlenir (graceful degradation, Bölüm 4 #9); OCR asla otomatik gönderim yapmaz.
- Gönderim: kategori fiş zorunluysa dosyasız fiş engellenir; limit aşımı `PolicyViolations`'a işaretlenir (plan); Submit → Workflow `ExpenseClaim`; onay → `PayrollAdjustment{Source=Expense}` aynı tx (plan); politika, talep sahibinin birimine/unvanına atanmış "Harcama onay süreci" ile çözülür → 11.3.4.
- Avans: Submit → Workflow `AdvanceRequest` ("Avans onay süreci"); onay → taksit planı (`InstallmentCount` yoksa tek kesinti), her taksit `PayrollAdjustment{Source=Advance}`; yabancı para avansta kesinti tutarı ödeme günü kuruyla TRY'ye sabitlenir [SenseİK kararı; doğrulanmalı]; çıkışta kalan bakiye tek kesinti (plan). Stajyer/dış kaynak için avans kapalı olabilir (tenant ayarı, Bölüm 3.1).
- FM ödemesi: `Leave.OvertimeConvertedToPayment` alınınca `PayrollAdjustment{Source=Overtime, Amount, IsGross, Reference=OvertimeRequestId}` oluşur; Leave tarafında çarpan değiştirilirse `Leave.OvertimePaymentRevised` ile kalem güncellenir; kilitli döneme giremez → Supplementary run → 11.3.5 / 11.3.7.
- "Ödemeler" projeksiyonu yalnız Expense şemasını okur (ExpenseClaim + AdvanceRequest/Installment + PayrollAdjustment); çapraz modül okuma yok.
- Açık avans bakiyesi `AdvanceBalance = Σ onaylı/ödenmiş avans − Σ Deducted taksit`; kartta "Borç" barı bu değeri gösterir (varsayım, doğrulanmalı).
- Zimmet aktarımı satır işleme: TCKN ile çalışan bul (yoksa satır hatası "çalışan kayıtlı değil"; TCKN eşleştirme altyapısı → 11.3.15); kategori find-or-create; `SerialNumber` doluysa aynı kategori + seri no ile mevcut varlık kullanılır, boşsa yeni varlık; `ReturnedAt` doluysa kapalı atama + `Available`, boşsa açık atama + `Assigned` (aynı varlıkta açık atama varsa hata: tek aktif atama); `Email` doluysa ve "bilgilendir" seçiliyse `Assets.AssignmentImported` → e-posta. Tarih formatı slash; sadece güncelleme modu mevcut atamayı (`EmployeeId + CategoryId + SerialNumber + AssignedAt`) günceller → 11.3.15.
- Çalışanın kendi zimmetlerini görmesi `Access.EmployeeCanViewOwnAssets` ayarına bağlı; kapalıyken `/app/assets` menüde görünmez ve `GET /assets/my` 403 döner (sunucu son söz).

**Akışlar**
1. Harcama (web): Talep → Harcama → Fiş ekle → Dosya seç → Kategori / Tutar / Fiş tarihi / Vergi oranı / Para birimi / Açıklama → Kaydet → [ikinci fiş …] → toplam görünür → Genel açıklama → **Gönder** → "Talebiniz yöneticinize iletilecektir" → Gönder → "Talebiniz gönderildi" → onaycıya e-posta + ana sayfa bildirimi → Kendi hesabım > Ödemeler'de durum takibi → onay → bordro kalemi / ödeme → Paid [Ekranda, part8 #1; part1].
2. Harcama (mobil): "+" veya Harcamalar → fiş fotoğrafı çek → OCR tutar + tarih ön doldurur → kalan alanlar → kaydet → gönder [Ekranda, part1 mobil].
3. Avans: Talep → Avans → Tutar (+ para birimi, tarih, taksit, açıklama) → Kaydet → "talep oluşturuldu" e-postası → onay sürecine göre yöneticiye → onay → "onaylandı" e-postası → Ödemeler'de takip → taksit kesintileri bordroda [Ekranda, part8 #13].
4. FM → ödeme: çalışan kartı > Fazla mesailer > onaylı kayıt > Ödemeye çevir (çarpan, net/brüt) → Ödemeler'e düşer (→ 11.3.5) [Ekranda, part8 #8].
5. Zimmet aktarımı: Ayarlar > Veri aktar > Zimmet > Şablon indir → doldur → Dosya yükle → kolon eşleştirme → (Sadece güncelleme modu) → Kaydet ve devam et → "Aktarım başarıyla tamamlanmıştır" → e-posta kolonu doluysa bilgilendirme [Ekranda, part8 #29 + Veri aktarımı].
6. Çalışan zimmet görüntüleme: Erişim ayarları > Hesap > Zimmet açık → çalışan kendi kartı / Hesabım > Zimmetler [Ekranda, part8 #10].
