**Alanlar** (Kolay İK adı → SenseİK alanı; seçenekler kaynak anahtarlı `employee.enum.{Enum}.{Value}`, tr varsayılan / en)
- Kimlik ve temel [Ekranda, part1 şablon; part8 #25]: **Ad**, **Soyad** (kart için yeterli) → `FirstName, LastName`; **Kimlik numarası** → `NationalId` (şifreli + `TcKimlik` VO; yabancı uyruklu 99 ile başlayan YKN kabulü [Aday]); **Doğum tarihi** → `BirthDate` (izin yaş kuralı için önemli: ≤18 / ≥50 → min 20 gün, → 11.3.5); **Cinsiyet** → `Gender{Male=Erkek, Female=Kadın, Other=Diğer, Unspecified=Belirtilmemiş}`; **Medeni hal** → `MaritalStatus{Single=Bekar, Married=Evli, Divorced=Boşanmış, Unspecified=Belirtilmemiş}`; **Çocuk sayısı** → `ChildCount`; **Eğitim durumu** → `EducationStatus{Graduate=Mezun, Student=Öğrenci}`; **Tamamlanan en yüksek eğitim seviyesi** → `HighestEducationLevel{Primary=İlkokul, MiddleSchool=Ortaokul, HighSchool=Lise, Associate=Ön lisans, Bachelor=Lisans, Master=Yüksek lisans, Doctorate=Doktora}` (tam liste (?) doğrulanmalı; "Meslek Yüksekokulu, çıraklık" gibi serbest ifadeler kabul edilmez); **Askerlik durumu** → `MilitaryStatus{NotCompleted=Tamamlanmadı, Completed=Tamamlandı, Deferred=Tecilli, Exempt=Muaf, DraftEvader=Yoklama kaçağı, Absentee=Bakaya}`; **Engel derecesi** → `DisabilityDegree{None, First=1. derece, Second=2. derece, Third=3. derece}` (boş bırakılabilir); **Kan grubu** → `BloodType{OPos="0+", ONeg="0-", APos, ANeg, BPos, BNeg, ABPos, ABNeg}` (Rh/parantez yazımı kabul edilmez).
- İletişim [Ekranda, part1; part8 #19/#10]: **İş e-postası** → `WorkEmail` (kiracı içinde unique; kullanıcı hesabının e-postası), **Kişisel e-posta** → `PersonalEmail`; **Kişisel/cep telefonu** → `MobilePhone`, **Ev telefonu** → `HomePhone`, **İş telefonu** → `WorkPhone` (rehberde gösterimi erişim ayarına bağlı); telefonlar E.164 saklanır, içe aktarımda başta 0 yok, boşluk/parantez yok; **Posta kodu** → `EmployeeAddress.PostalCode` (plaka koduyla karıştırılmamalı).
- Genel / istihdam [Ekranda, part1; part8 #25]: **İşe başlama tarihi** → `HireDate`; **İzne esas hak ediş tarihi** → `LeaveAccrualStartDate` (varsayılan HireDate; gerçek tarih yazılır, "bir yıl sonrası" yazılmaz — sistem ilk hak edişi bir yıl sonra verir; → 11.3.5); **Sözleşme türü** → `ContractType{Indefinite=Süresiz, FixedTerm=Süreli}` ("belirli/belirsiz" gibi serbest ifade kabul edilmez); **Çalışma şekli** → `EmploymentType{FullTime=Tam zamanlı, PartTime=Yarı zamanlı, Temporary=Geçici, Contract=Kontratlı, Freelance=Serbest çalışan, Intern=Stajyer, Mobile=Gezici/Mobil (?)}` + [Mevzuat][Aday] `Apprentice=Çırak, Seasonal=Dönemsel/Mevsimlik, AgencyWorker=Geçici iş ilişkisi, Subcontractor=Alt işveren çalışanı` (TİS yetki sayımı, İSG eşiği için ayrım); **Çalışma tablosu / Çalışma takvimi** → `WorkScheduleId` (Attendance, atama tarihli; → 11.3.6); **İzin kuralı** → `LeaveRuleSetId` (varsayılan kural seti; → 11.3.5); **İşten ayrılma tarihi** → `TerminationDate`; **İşten ayrılma nedeni** → `TerminationReasonId` (aşağıda).
- Kariyer [Ekranda, part8 #25/#33; part1]: **Pozisyon ekle**: **Şirket**, **Şube**, **Departman**, **Proje** (özel seviye), **Ünvan**, **Onay süreci birimi** (özel seviye) → `EmployeeOrgAssignment{OrgUnitTypeId, OrgUnitId}` (kiracının seviye listesi, → 11.3.2); **Yönetici / İlk yönetici** → `DirectManagerId` + `CareerHistory.ManagerEmployeeId`; **Pozisyon başlama tarihi** → `CareerHistory.ValidFrom` (işe başlamadan farklı olabilir: 90 gün eğitim sonrası göreve başlama); **Çalışma şekli** kariyer kaydında da tutulur (`CareerHistory.EmploymentType`).
- Maaş bloğu [Ekranda, part1]: **Maaş geçerlilik tarihi** → `SalaryHistory.EffectiveFrom` (zorunlu), **Maaş** → `Amount` (sayısal), **Para birimi** → `Currency` (ISO 4217; Kolay İK kısaltmaları "TL/Euro" içe aktarımda `TRY/EUR` alias), **Maaş türü** → `SalaryType{Net, Gross=Brüt}` ("asgari" seçeneği yok), **Ödeme düzeni** → `PayFrequency{Monthly=Aylık, Daily=Günlük, Yearly=Yıllık, Weekly=Haftalık, Hourly=Saatlik}`, **Yol yardımı** → `TransportAllowance?`, **Yemek yardımı** → `MealAllowance?` (Payroll sabit kalemleri `TRANSPORT`, `MEAL_CASH/CARD` ile senkron; kalem tipi kiracı ayarı → 11.3.7).

- Özel alanlar [Ekranda/Müşteri, part1; part8 #10/#32]: kiracı tanımlı; örnekler **Beden**, **Almanca bilgisi**, **Emeklilik durumu (Evet/Hayır)**, **Önceki projeler**, **Sertifika**, **Dil** → `CustomFieldDefinition{Key, Name, DataType(Text/Number/Date/Boolean/SingleSelect/MultiSelect), Options[], Section(Personal/Career/Other), IsRequired, IsEmployeeEditable, EmployeeEditRequiresApproval, IsReportable=true, IsSensitive, SortOrder, IsActive}` + `CustomFieldValue{EmployeeId, DefinitionId, Value jsonb}`. Şablonda kolon başlığı = alan adı.

**İş kuralları ve hesaplama**
- **Hızlı ekleme** [Ekranda, part8 #18/#25]: Ad + Soyad ile kart oluşur; e-posta girilince davet mümkün; "ne kadar çok veri girilirse raporlar o kadar detaylı" (satış söylemi). SenseİK: `CreateEmployee{FirstName, LastName, WorkEmail?, PersonalEmail?, HireDate?, LeaveRuleSetId?, WorkScheduleId?, OrgAssignments?[]}`; HireDate yoksa `Status=Draft` (listede "Eksik bilgi" rozeti; izin tahakkuku, bordro, headcount KPI dışında); HireDate girildiğinde `EmployeeHired` bir kez yayınlanır → Leave hak ediş (varsayılan kural seti; farklı kural istenirse eklerken seçilir, part8 #31), Attendance varsayılan çalışma takvimi ("Genel çalışma tablosu", → 11.3.6), Identity davet hazırlığı, Documents klasörü, Billing seat. `CareerHistory(Hire)` ilk pozisyon atamasında veya HireDate ile (ValidFrom = PositionStartDate ?? HireDate) oluşur; `SalaryHistory` opsiyonel. Sihirbaz (plan) atomik yolu korur.
- **Davet önceliği** [Ekranda, part8 #19]: her iki e-posta doluysa davet **iş e-postasına** gider; SenseİK `TenantSettings Employee.Invite.EmailPrecedence=Work|Personal` (varsayılan Work); e-posta yoksa buton pasif; toplu **Giriş bilgilerini gönder** e-postası olmayanları "atlandı" olarak raporlar (→ 11.3.1).
- **Yöneticiden hak ediş** [Ekranda, part8 #25]: işe başlama tarihi girilince yıllık izin hak edişi otomatik hesaplanır ve İzinler barında görünür; `LeaveAccrualStartDate` ayrı tarihse kümülatif hesap (→ 11.3.5). Validasyon: `LeaveAccrualStartDate <= HireDate` uyarı (öncesi olabilir: grup geçişi), `PositionStartDate >= HireDate`, `TerminationDate >= HireDate`.
- **Pozisyon başlama tarihi ≠ işe başlama tarihi** [Ekranda, part1]: kariyer ilerlemesi (uzman → müdür) veya eğitim sonrası göreve başlama; her kariyer kaydı kendi ValidFrom'unu taşır; aynı anda tek açık kayıt (ValidTo null), yeni kayıt öncekini ValidFrom−1 ile kapatır.
- **Maaş bloğu bütünlüğü** [Ekranda, part1]: geçerlilik tarihi ve tutar olmadan para birimi/tür/düzen/yardımlar kaydedilmez (içe aktarımda blok yok sayılır); tutar sayısal, metin/kısaltma yok. Plan kuralı korunur: kilitli bordro dönemine giren maaş değişikliği reddedilir (`Payroll.PeriodLocked`); `employee.salary.edit` onaylı değişiklik → RequestType `SalaryChange` (3.4).
- **Özel alan kuralları** [Ekranda, part1; part8 #10/#32]: alan önceden tanımlı olmalı; varsayılan görünürlük yalnız yetkililer; **Erişim ayarları → Özel alanlar** açılınca çalışanlar ve birim yöneticileri görür (tek anahtar, `TenantSettings Employee.CustomFields.VisibleToEmployees`); `IsEmployeeEditable` alanları çalışan **Hesabım**'dan düzenler (beden örneği); `EmployeeEditRequiresApproval` ise `ProfileChange` talebi; `IsReportable` alanlar rapor/özel rapor kolonuna girer (`DataSourceField` kataloğu kiracıya göre dinamik; → 11.3.12); `IsSensitive` alanlar `employee.sensitive.view` ister.
- **İşten ayrılma nedeni** [Ekranda, part1]: sistem listesi (duyulan örnekler **Ölüm**, **Askerlik**) + kiracı kendi nedenini oluşturur; içe aktarımda ad ile eşleşir. SenseİK: `TerminationReason` sistem seed'i (aşağıda) + `DefaultSgkExitCode` (SGK çıkış kodu listesi Payroll'da, → 11.3.7) + `DefaultTerminationType`; sihirbazda neden seçilince SGK kodu ve fesih türü ön-dolu, düzenlenebilir. Ayrılan çalışanların sistemde tutulması zorunlu değil (içe aktarımda ayrılma kolonları opsiyonel); liste varsayılan filtresi `Status=Active`, ayrılanlar filtreyle görünür.
- **İş güvencesi kontrolü** [Mevzuat, part5 #3]: kapsam = aynı iş kolu kodundaki tüm işyerlerinde toplam çalışan > `LegislationParameter("JobSecurity.MinHeadcount")` (30; il sınırı yok, yurt dışı çalışan dahil; birlikte istihdamda grup toplamı) ∧ kıdem > `JobSecurity.MinSeniorityMonths` (6; deneme süresi ve askı süreleri dahil; aynı işverenin farklı işyerleri ve fasılalı dönemler birleşik; yer altı işçisinde aranmaz: `IsUndergroundWorker`) ∧ `ContractType=Indefinite` ∧ `!IsEmployerRepresentative`. Kapsamdaysa ve `TerminationType=ValidCause_Art18` ise uyarı: "fesih yazılı yapılmalı, savunma alınmalı"; belge kontrol listesi (fesih bildirimi, savunma talep yazısı, işçi savunması) Documents'a düşer (→ 11.3.9). Belirli süreli sözleşme, ikale ve işçinin haklı feshinde işe iade uyarısı gösterilmez.
- **Toplu işten çıkarma eşiği** [Mevzuat][Aday, part3 V2]: son 30 günlük pencerede (ilk fesihle başlar) fesih sayısı ≥ eşik (`CollectiveDismissal.Thresholds` json: 20–100 çalışan → 10; 101–300 → %10; 301+ → 30) → uyarı + 30 gün önceden bildirim hatırlatıcısı; md.24/25, istifa, arabulucu anlaşması, ihale bitişi sayımdan düşülür; 6 ay yeniden alım önceliği (ATS eşleşmesi → 11.3.11) ve 8 ay geçici iş ilişkisi yasağı hatırlatıcısı. Kolay İK'da doğrulanmadı; öneri.
- **Kıdem birleştirme** [Mevzuat, part2 #3; part3 V2; part5 #3]: `EmploymentPeriod` çalışanın her çalışma dönemini tutar. **Yeniden işe giriş** (`RehireEmployee{HireDate, MergePreviousPeriods}`): önceki dönemler kıdem/ihbar tazminatı ödenmiş olsa bile **izin kıdemine dahil**; istisna: önceki dönemin yıllık izinleri kullandırılmış veya çıkışta ücreti (`UNUSED_LEAVE_PAY`) ödenmişse o dönem "tasfiye edilmiş" sayılır ve yeni dönemde **sayılmaz** (Yargıtay güncel çizgisi [Mevzuat → 11.3.5 eki C2]) → çıkışta `EmploymentPeriod.LeaveSettledAtExit` işaretlenir, `GetSeniorityAsync(purpose: Leave)` bu dönemleri hariç tutar; `LeaveAccrualStartDate` önerisi = sayılan ilk dönem başlangıcı (ara boşluklar ve `LeaveSettledAtExit` dönemleri düşülerek); yeniden işe girişte "önceki dönem izin kıdemine sayılsın mı" onay kutusu bu bayraktan ön-dolar, İK değiştirebilir (audit); **kıdem tazminatı kıdemi** (`SeniorityStartDate`) `SeverancePaid=true` dönemleri hariç tutar; ikisi de kullanıcı tarafından geçersiz kılınabilir (audit). **Birlikte istihdam** (aynı grup, aynı zaman diliminde birden fazla işverene hizmet): süreler toplanır; **işyeri devri** (md.6): devir tarihi + devir anındaki ücret snapshot'ı (`TransferSalarySnapshot`), devreden 2 yıl müteselsil sorumlu (`BusinessTransfer.JointLiabilityYears`), ihbar yalnız devralanda; grup içi transfer kuralları → 11.3.2. Ücretsiz doğum izninin (6 ay) izin kıdeminden düşmesi → 11.3.5. Mali müşavir/avukat doğrulaması gerekli.
- **Askı halleri** [Mevzuat, part2 #3; part3 V2]: askerlik (muvazzaf; `SuspensionReason=MilitaryService` — bedelli askerlik 21 gün askı değil, izin türü `PaidMilitaryService`, çalışma süresinden sayılır → 11.3.5 eki C6), sağlık raporu, zorlayıcı nedenler, gözaltı/tutukluluk, ailevi nedenler, sendika yöneticiliği → `Status=Suspended` + `SuspensionReason`; kayıt ve kullanıcı hesabı aktif kalır (hesap kilidi kiracı ayarı `Employee.Suspension.DisableLogin` [Aday]); tahakkuk/bordro/puantaj etkisi ilgili modüllerde (→ 11.3.5, 11.3.6, 11.3.7); iş güvencesi kıdeminde askı süreleri sayılır.
- **Sendika** [Mevzuat, part3 V2]: üyelik, işverene bildirim tarihi (TİS'ten yararlanma bu tarihten itibaren), kapsam türü (üye / dayanışma aidatlı / sendika onaylı: greve katılan, işveren vekili / kapsam dışı), sendika yöneticiliği → askı; ayrılırsa kıdem tazminatı hakkı notu (→ 11.3.7). Özel nitelikli kişisel veri: AES-GCM + `employee.union.view` + Auditor'da maskeli.
- **Sözleşme belgesi uyumu** [Mevzuat, part4 #6]: süre ≥ `Contract.WrittenRequiredMinMonths` (12) ise yazılı sözleşme zorunlu; sözleşme belgesi yoksa işe girişten `Contract.WorkingConditionsDocDeadlineDays` (60) içinde "çalışma koşulları belgesi" hatırlatıcısı (`Reminder.Type=ContractDocumentDue`; <1 ay istisnası) → belge şablonu ve eksik belge kuralı 11.3.9.
- **Çalışma modeli** [Aday, part5 #12 müşteri pratiği]: `WorkModel{Office, Hybrid, Remote}` alanı; departman bazlı ofis günü hedefi ve ölçüm → 11.3.6/11.3.12. Kolay İK'da doğrulanmadı.
- **Kariyer hareketi türü** [Müşteri, part5 #1; Mevzuat, part3 V2]: terfi (dikey) / yatay hareket ayrımı → `ChangeType{Hire, Promotion, LateralMove, Demotion, TitleChange, ManagerChange, GroupTransfer, BusinessTransfer, Rehire, Other}`; kariyer yolu oranı = Promotion / (Promotion + LateralMove) (→ 11.3.12); terfi/pozisyon değişikliğini akışta duyurma opsiyonel `FeedItem{Promotion, PositionChange}` (→ 11.3.13).
- **Toplu işlemler** [Ekranda, part8 #19/#22/#24/#31]: filtre (şube, departman…) → satır seçimi veya **Tümünü seç** (filtreye uyan tüm kayıtlar, sunucu tarafında çözülür; sayfa değil) → **İşlem seç** → parametre → onay. Aksiyona özgü uyarılar: **İzin kuralı ata** → "İzin kuralı işe başlama tarihinden itibaren yürürlüğe girecek ve yeniden hesaplanacak" (→ 11.3.5); **Çalışma takvimi ekle** → atama tarihinden itibaren geçerli, geriye dönük değişmez (→ 11.3.6); **Yönetici ata** → yönetici adı yazılarak (typeahead) seçilir, geçerlilik tarihi varsayılan bugün; **Giriş bilgilerini gönder** → seçilen her çalışana davet (→ 11.3.1). Sonuç satır bazlı (başarılı/atlandı/hata + neden), Excel'e aktarılır; `Idempotency-Key` zorunlu; eşik (`GridOptions.BulkAsyncThreshold`, IOptions, varsayılan 50) üstü Hangfire job + SignalR ilerleme.
- **Yönetici değişimi** [Ekranda, part8 #24/#33; plan 3.2/3.4]: `DirectManagerId` güncellenince `CareerHistory.ManagerEmployeeId` tarihli kayıt, `EmployeeHierarchy` closure yenileme, döngü kontrolü, `ManagerChanged` → Workflow bekleyen görevleri yeniden atar; "ilk yönetici" varsayılan onaycıdır (→ 11.3.4).
- **Birim yöneticisi kapsamı** [Ekranda, part8 #32]: yalnız yetkilendirildiği birim(ler)deki kartlara erişir; kişisel bilgileri ve kariyeri düzenler; kendi birimine çalışan ekler (Şirket/Şube alanları kendi kariyerinden ön-dolu, değiştirilebilir); maaş/ödeme görünürlüğü "Çalışanların ödeme ve maaş bilgilerine erişebilsin" anahtarına, özel alanlar Erişim ayarına bağlı; **Kendin oluştur** raporu yok, kendi birim raporları anahtara bağlı (→ 11.3.12). Aynı kişi birden fazla birime yetkilendirilebilir.
- **Self-servis düzenleme** [Ekranda/Müşteri, part1; part4 #3; part8 #18]: çalışan kendi kartını görür ve günceller; düzenlenebilir bölümler `Employee.SelfService.EditableSections[]` (varsayılan: iletişim, adres, acil kişi, bağımlılar, `IsEmployeeEditable` özel alanlar; banka/kimlik/kariyer İK'ya ait), `Employee.SelfService.RequireApproval` (varsayılan true → `ProfileChangeRequest` → Workflow `ProfileChange`; onayda alanlar uygulanır, `EmployeeProfileChanged` event); kendi belgelerini/verisini indirme (→ 11.3.9, KVKK veri taşınabilirliği).
- **Hassas alanlar**: TCKN, IBAN, maaş, sağlık/engel, sendika → ayrı izinler + DTO maskeleme (plan); `Auditor`/`ExternalAccountant` maskeli görür.

**Akışlar**
- **Çalışan ekleme** [Ekranda, part8 #18/#25]: Çalışanlar → **Yeni çalışan ekle** → Ad, Soyad (→ birim yöneticisi için Şirket/Şube ön-dolu; İşe başlama tarihi, Yönetici, Çalışma şekli opsiyonel) → **Kaydet** → kart açılır (Genel: İşe başlama tarihi, Sözleşme türü, Çalışma tablosu; Kariyer: Pozisyon ekle; Kişisel bilgiler) → e-posta gir → Kaydet → **Davetiye gönder** → çalışan e-postadaki davetle parola oluşturur → giriş → kendi kartını görür/günceller, sol menüden talepler (→ 11.3.5, 11.3.8, 11.3.9). SenseİK: `/admin/employees/new` modal (hızlı) veya sihirbaz (tam); Draft → Active geçişi HireDate ile.
- **Davet** [Ekranda, part8 #18/#19]: tekil kart → üç nokta → **Davetiye gönder** (Evet/Hayır onayı); toplu → **Toplu işlemler → Giriş bilgilerini gönder**. Ayrıntı (Invitation, token, süre, yeniden gönder) → 11.3.1.
- **Yönetici atama** [Ekranda, part8 #24/#33]: (a) kart → **Kariyer** → **Pozisyon** → **Düzenle** → Yönetici; (b) **Toplu işlemler → Yönetici ata** → ad yaz → devam; (c) **Çalışanlar → Organizasyon şeması** → kişi → **Düzenle**; (d) özlük şablonunda **ilk yönetici** kolonu, "Sadece güncelleme modu" (→ 11.3.15).
- **Kariyer / pozisyon ekleme** [Ekranda, part8 #25/#33]: **Kariyer → Pozisyon ekle** → seviyeler sırayla (Şirket → Şube → Departman → Proje → Ünvan → Onay süreci birimi) → Yönetici → Pozisyon başlama tarihi → Çalışma şekli → Kaydet → yeni `CareerHistory` kaydı, önceki kapanır; ChangeType seçimi (Terfi/Yatay/Ünvan/Diğer) SenseİK eklemesi.
- **Self-servis profil güncelleme** [Ekranda, part1]: **Hesabım / Profili görüntüle** → **Düzenle** (web) / **Hesap → Düzenle** (mobil) → izinli bölümler → Kaydet → doğrudan uygulanır veya onaya gider (İK inbox) → çalışana sonuç bildirimi.
- **Birim yöneticisinin çalışan eklemesi** [Ekranda, part8 #32]: birim yetkilendirmesi (→ 11.3.1) → Çalışanlar (yalnız kendi birimi) → Yeni çalışan ekle → şirket/şube ön-dolu → yönetici, çalışma şekli, kişisel bilgiler → Kaydet.
- **Yeniden işe giriş** [Mevzuat]: ayrılmış kart → **Yeniden işe al** → yeni HireDate, birleştirme seçimi → yeni `EmploymentPeriod`, `Status=Active`, önerilen `LeaveAccrualStartDate`/`SeniorityStartDate` gösterilir → `EmployeeRehired` (Leave yeniden hesap, Identity hesap açma, Billing seat).
- **İşten çıkış** (plan sihirbazı + eklemeler) [Ekranda/Mevzuat]: Ayrılma tarihi → Ayrılma nedeni (sistem/özel) → fesih türü + SGK kodu ön-dolu → iş güvencesi ve toplu çıkarma uyarıları → açık zimmet/avans/izin bakiyesi kontrolleri (3.21 saga; kalan izin ücreti ödendi veya izinler tamamen kullandırıldıysa `EmploymentPeriod.LeaveSettledAtExit=true`; eksi izin bakiyesi yalnız bilgi, ücretten kesinti yok → 11.3.5 eki C2, C4) → belge listesi (ibraname, fesih bildirimi, hizmet belgesi, SGK çıkış bildirgesi; → 11.3.9) → `EmployeeTerminated{TerminationType, ReasonCode, SgkExitCode}`.
- **Veri aktarımı** [Ekranda, part1; part8 #33]: Ayarlar → Veri aktar → Özlük bilgileri → Şablonu indir → doldur → yükle → kolon eşleştirme → (Sadece güncelleme modu) → Kaydet. Yalnız bu bölüme özgü kural: eşleştirme **Kimlik no + Ad + Soyad**; şablon başlıkları değiştirilemez, gereksiz kolon silinebilir; seçenek değerleri yukarıdaki enum listeleriyle eşleşir; yönetici, birim ve özel alan sistemde önceden var olmalı; **Çalışan listesi raporu** Excel'i toplu güncelleme kaynağı olarak kullanılır. Geri kalanı → bkz. 11.3.15.
